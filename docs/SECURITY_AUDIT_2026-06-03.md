# Security Audit — orchestrator
**Date**: 2026-06-03
**Auditor**: SEC-Orchestrator (Claude Opus 4.7, Plan agent)
**Scope**: code at HEAD (commit `2ef9ae7`), FastAPI routes & auth, RQ worker subprocess pipeline, SSE log/metrics streams, docker-compose stack (api + worker + redis + mlflow), CI workflow, deps state, git history (5 commits).

## Executive summary

The orchestrator is the largest attack surface in the workspace (network listener + subprocess executor + secrets injector) and contains one **Critical** issue and two **High** issues that compound: (1) `require_token()` silently disables auth when `API_TOKEN` is empty — combined with the documented `ALLOW_LAN=true` option this becomes unauthenticated remote subprocess execution; (2) `_make_env()` copies the full `os.environ` into every Hydra subprocess and `hydra_overrides: list[str]` is passed un-sanitized to those subprocesses, which means an authenticated caller can exfiltrate any env var (including `API_TOKEN`, `DATABASE_URL`, `HF_TOKEN`) by injecting an OmegaConf `${oc.env:VAR}` resolver into an override and reading it back through the SSE log stream — the secret sanitizer regex only masks four well-known shell-assignment patterns and is bypassed by OmegaConf-resolved values; (3) `uv.lock` is **explicitly listed in `.gitignore`** and is not tracked, so CI resolves dependencies non-reproducibly on every run. Secondary issues: SSE endpoints expect a Bearer header that browser `EventSource` cannot send (so the front-end will be tempted to fall back to query-string tokens, which leak through logs); containers run as root with no `cap_drop`/`read_only`/`no-new-privileges`; the worker container has RW access to two sibling repos; no rate limiting; CI actions floating-tag pinned and no `permissions:` block; no `SECURITY.md` and no `.pre-commit-config.yaml` despite the Makefile referencing one. Positive controls: 100% SPDX coverage (31/31 `.py`), `secrets.compare_digest` used correctly, no `shell=True`, no `eval`/`exec`/`pickle`, Pydantic schemas on every mutating route, git history clean of leaked credentials.

| ORC-001 | Critical | Network / Auth | `src/orchestrator/api/auth.py:28-30` — `require_token()` returns `None` (pass-through) when `settings.api_token` is empty. The default value in `core/config.py:24` is `api_token: str = Field(default="")`. A first-boot user who runs `docker compose up` before `make token` (or who simply forgets to set `API_TOKEN`) gets a fully unauthenticated API. Combined with `ALLOW_LAN=true` (which flips `bind_host` to `0.0.0.0` in `config.py:54-55`), this yields unauthenticated, remote-reachable subprocess execution via `/api/v1/runs/{collect,train,eval}`. Log a Critical-level warning at boot if auth is disabled. Add a test `test_empty_api_token_rejects_request`. | S |
| ORC-002 | High | Validation / Secrets | `hydra_overrides: list[str]` (`api/schemas.py:60,69,77`) is accepted on `/runs/collect|train|eval` with no character whitelist, no length cap, no resolver-prefix filter. The list is forwarded verbatim into `argv` (`api/routes/runs.py:80,99,115`) and executed as Hydra CLI arguments inside the lerobot subprocess. Because `_make_env()` (`worker/jobs/base.py:43`) copies the entire `os.environ` — which under docker-compose includes `API_TOKEN`, `HF_TOKEN`, `WANDB_API_KEY`, `DATABASE_URL`, `REDIS_URL` (see `docker/docker-compose.yml:59-65`) — an authenticated caller can inject `+leak=${oc.env:API_TOKEN}` (or any other var name). OmegaConf will resolve the interpolation when the child Hydra app composes its config and the resolved value flows through stdout (e.g. via Hydra's `config print` or any `logger.info(cfg)` call in the consumer scripts) into the SSE log stream. The `_sanitize_secret` regex (`api/routes/streams.py:42-47`) matches only `Bearer\s+\S+`, `HF_TOKEN=\S+`, `API_TOKEN=\S+`, `WANDB_API_KEY=\S+` — it does NOT match OmegaConf-resolved values appearing as bare strings, nor `hf_*`/`ghp_*`/`sk-*`/JWT/AWS-key prefixes, nor multi-line YAML dumps. End-to-end this is a privilege-escalation primitive: authenticated user → token holder. | (a) Validate `hydra_overrides` with a strict regex on the API side: `^[A-Za-z0-9_.+@/=,\-]+$` and reject any value containing `${oc.env:` / `${oc.create:` / `${oc.decode:` / `${oc.deprecated:` (the dangerous resolvers). (b) Whitelist `_make_env()` to forward only `MLFLOW_TRACKING_URI`, `HF_TOKEN`, `WANDB_API_KEY`, `PATH`, `HOME`, `LANG`, `LC_*`, `PYTHONPATH`, `CUDA_VISIBLE_DEVICES` — never copy the full env. (c) Extend `_SECRET_PATTERNS` with `hf_[A-Za-z0-9]{20,}`, `ghp_[A-Za-z0-9]{36}`, `sk-[A-Za-z0-9]{20,}`, `eyJ[A-Za-z0-9_\-]{20,}\.[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+` (JWT), `AKIA[0-9A-Z]{16}`, `aws_secret_access_key\s*=\s*\S+`. (d) Cap `len(hydra_overrides) <= 32` and each entry `<= 256` chars. Add unit tests for each rejected pattern and a PoC test that confirms `${oc.env:API_TOKEN}` is rejected at the API boundary. | M |
| ORC-003 | High | Deps | `.gitignore:52` contains the line `uv.lock` → the lockfile is **explicitly excluded** from version control. `git ls-files | grep uv.lock` returns nothing; the 308-KB `uv.lock` present on disk is uncommitted. CI (`.github/workflows/ci.yml:23,47`) runs `uv sync --extra dev` without `--locked`, so every CI run performs a fresh resolution against PyPI — Docker builds, lockfile drift, and CVE exposure are non-reproducible. Of the 5 workspace repos, this is the second one missing a tracked lockfile (`my-robot-stack` is the other, MRS-001). The locked-decisions doc claims "FastAPI + SQLite + RQ + Redis" stack — pinning is implied. | (1) Remove `uv.lock` from `.gitignore`. (2) `uv lock && git add uv.lock && git commit`. (3) Change CI to `uv sync --locked --extra dev` so PRs that don't update the lock fail fast. (4) Add a CI job running `uv run pip-audit --strict` on the lockfile. | S |
| ORC-004 | High | Network / Auth | SSE endpoints `/api/v1/runs/{run_id}/logs` and `/api/v1/runs/{run_id}/metrics` (`api/routes/streams.py:89,197`) are protected by `Depends(require_token)`, which expects a Bearer header. Browser `EventSource` cannot set custom headers (a long-standing limitation). The natural workaround future frontends adopt is `?token=...` in the URL, which (a) lands in nginx/uvicorn access logs, (b) lands in browser history, (c) is exposed via `document.referrer`, (d) is captured by `/api/docs` Swagger if the URL is shared. The current code has no transport for SSE auth at all — the `eventsource` JS API would simply fail with 401, pushing the frontend author toward the query-string anti-pattern. ADR-002 explicitly plans for a frontend in the next sprint, so this lands soon. | Adopt one of: (i) per-stream short-lived signed token endpoint (`POST /api/v1/runs/{run_id}/stream-token` returns a 60-second HMAC over `(run_id, exp)`, then SSE accepts `?stream_token=...` and the regex sanitizer redacts it from logs); (ii) move to WebSockets which DO support headers via subprotocol; (iii) require a same-origin cookie set by a `/login` endpoint. Document the choice in ADR. Until then, document explicitly that browser SSE clients are unsupported. | M |
| ORC-005 | High | Docker / Privileges | `docker/docker-compose.yml` services (api, worker, redis, mlflow) run as **root** with no `user:`, no `cap_drop: [ALL]`, no `read_only: true`, no `security_opt: [no-new-privileges:true]`, no `tmpfs`/`pids_limit`/`mem_limit`. The `worker` service binds `lerobot-playground-portfolio` and `ml-core` **read-write** (lines 106-107) — a compromised dependency invoked by a Hydra subprocess can mutate sibling repo source code on the host. The `mlflow` container exposes port 5000 via `${MLFLOW_HOST:-127.0.0.1}` (good default), but the `api` service publishes `0.0.0.0:8000` *inside its own command* (`--host 0.0.0.0`) — fine when the port bind is `127.0.0.1:8000` (line 57), broken the moment a deployer changes `API_HOST` to `0.0.0.0` without also flipping `ALLOW_LAN` (these are two independent settings). | Add to each service: `user: "1000:1000"`, `cap_drop: ["ALL"]`, `security_opt: ["no-new-privileges:true"]`, `read_only: true` (with explicit `tmpfs: [/tmp]`), `pids_limit: 512`, `mem_limit: 4g` (tune per service). Build a non-root user in the Dockerfile (`RUN useradd -u 1000 -m orch && USER orch`). Change the worker's RW mounts to RO unless a specific write path is required, and only mount the specific writable subpaths (`checkpoints/`, `eval_reports/`, `outputs/`). Add a single `API_BIND` env consolidating host+lan to eliminate the two-knob footgun. | M |

| ORC-008 | Medium | Validation | `/api/v1/runs/eval` accepts `checkpoint_path: str` (`api/schemas.py:73`) with **no validation** — the value is interpolated directly into the Hydra arg `+eval.checkpoint_path={body.checkpoint_path}` (`api/routes/runs.py:109`). | ORC-009 | Medium | Validation | `/api/v1/configs/*` and `/api/v1/artifacts/*` (`api/routes/configs.py`, `api/routes/artifacts.py`) read YAML and `eval_report.json` from `settings.lerobot_repo`. `core/artifacts.py:202-207` does `yaml.safe_load(raw)` on every dataset config — safe. ### Positive controls verified
- **SPDX coverage**: 31/31 `.py` files under `src/` carry `SPDX-License-Identifier: Apache-2.0`. 100%.
- **No `LicenseRef-Proprietary`** in the tree (Apache-2.0 repo discipline respected).
- **`secrets.compare_digest`** is used correctly for the Bearer token comparison (`api/auth.py:33`).
- **No `shell=True`, no `eval`, no `exec`, no `pickle.load`** in `src/`. `yaml.safe_load` is used (never `yaml.load`).
- **Pydantic schemas** on every mutating endpoint (`schemas.py` `CollectRequest`, `TrainRequest`, `EvalRequest`).
- **CORS**: not enabled by default — `main.py:27-28` explicitly comments "frontend must be reverse-proxied or same-origin".
- **`subprocess.Popen`** is called with an argv list (no shell), `cwd` is a pre-computed trusted path, `env` is explicit.
- **Database**: SQLAlchemy parameterized queries (no string concat); `text("SELECT 1")` in `system.py:37` is a trivial literal.
- **Git history clean**: no credentials committed in the 5 commits.
- **`.gitignore`** correctly excludes `.env`, `.env.local`, `*.pem`, `*.key`, `data/`, `mlruns/`, etc.

## Out of scope

- Runtime security of the lerobot/ml-core CLIs invoked by the worker (`collect.py`, `train.py`, `eval.py`) — covered by `lerobot-playground-portfolio` and `ml-core` audits (LRB-*, MLC-*).
- MLflow tracking server hardening (the container exposes `0.0.0.0:5000` *inside* its network namespace but binds `127.0.0.1:5000` on the host — MLflow auth is upstream's concern).
- Redis hardening (no AUTH password configured; container is on the compose-private network and not host-exposed — acceptable for single-user single-machine; revisit if multi-tenant).
- Upstream CVEs in pinned wheels — defer to `pip-audit` once ORC-003 is fixed.
- Tauri / launcher-based deployment (ADR-002 Proposed) — to be audited when implemented.
- Production multi-user, Internet-exposed deployment scenarios — explicitly out of design scope per `memory/arch_orchestrator.md` ("single-user, single-machine").
- Hardware safety of any robot driven via this orchestrator (covered by `my-robot-stack` and `robotics-platform-template` HAL audits).

## Recommandations transverses

- **One-PR security baseline** (closes ORC-001 + ORC-002 + ORC-003): make `API_TOKEN` mandatory at boot, whitelist `_make_env()` to a known set of forwarded vars, reject `${oc.env:...}` / `${oc.create:...}` in `hydra_overrides`, commit `uv.lock` (drop the `.gitignore` line), switch CI to `uv sync --locked`. These four changes neutralize the only unauthenticated-RCE plus the only auth-to-secret-exfiltration paths and make the deps surface reproducible. Highest ROI in the audit.
- **Docker hardening pass** (closes ORC-005): non-root user in the Dockerfile, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `read_only: true` with explicit `tmpfs`, narrow the worker's RW mount surface to specific subpaths. Pair with a `docs/RUNBOOK.md` section explaining the threat model and the deliberate single-user assumption.
- **Frontend auth strategy ADR** (closes ORC-004): write a short ADR-003 deciding signed short-lived stream tokens vs. WebSockets vs. cookie-session, BEFORE the first frontend line is written. The wrong default (query-string Bearer) is sticky once shipped and leaks through logs forever.
- **CI + pre-commit alignment** (closes ORC-006 + ORC-007): one PR that adds `.pre-commit-config.yaml` (ruff/ruff-format/mypy/gitleaks + workspace-contamination guard + remote-allowlist guard) and aligns CI: `permissions: read`, full-SHA action pins, Dependabot, `pip-audit` job, `uv sync --locked`. Same pattern already proven across the four sibling repos.
